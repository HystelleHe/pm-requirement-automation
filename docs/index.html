Build · 功能需求

做什么 → 怎么做

适合已决定要做某个功能，需要完整竞品参考 + PRD 落地的场景

  • 竞品关键词发现~3–6k tokens
  • Tavily 网页搜索 + 摘要（搜索 API）
  • Research 报告整合含推理 tokens
  • 需求拆解（用户故事）~4–5k tokens
  • PRD 初版生成（Kimi）~22–50k tokens
  • Critic 审校（GLM）≤2 轮
Discover · 探索调研

该做什么 → 洞察

适合方向模糊、需要先探索市场 / 趋势 / 机会的场景，不强行输出 PRD

  • 竞品关键词发现~2–4k tokens
  • Tavily 网页搜索 + 摘要（搜索 API）
  • 洞察备忘录生成~1–2k tokens
  • —— Breakdown / PRD 跳过 ——节省 80%+
💡 产出包含：核心洞察 / 市场趋势 / 机会点 / 风险 / 开放问题
适合在 PRD 前做方向验证
设计思路

三个核心决策

每个决策背后有明确的 tradeoff 考量

🔀

跨家 Critic，避免自我审校盲点

PRD 生成用 Kimi-K2，审校用 GLM-5（智谱）。同一模型既当作者又当评审容易互相迁就、漏掉明显矛盾。实测跨家 Critic 能发现结构歧义和目标冲突。

🪶

n8n 只做薄编排，能力层独立

n8n workflow 只有 5 个 HTTP 节点，所有业务逻辑全在 FastAPI 服务里。这意味着可以随时换掉 n8n，用 cron / GitHub Actions / Slack 触发，不影响产出质量。

🛑

Discover 路径：不为探索型需求强行写 PRD

早期验证发现「开放型需求被 PRD 模板硬塞 user story 会产生违和感」。Discover 路径不接 Breakdown/PRD，输出洞察备忘录更匹配方向模糊阶段的真实诉求。
